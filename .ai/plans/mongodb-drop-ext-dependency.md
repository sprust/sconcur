# Убрать зависимость от ext-mongodb

> **Статус: реализовано, замеры в разделе 9.** Обратная совместимость ломается
> сознательно (решение владельца): документы возвращают собственные
> value-объекты вместо `MongoDB\BSON\*`.

## 1. Что сейчас и почему это быстро

Документы ездят между PHP и Go сырым BSON. Go отдаёт `bson.Raw` прямо из
драйвера, не разбирая; PHP кодирует и декодирует через `ext-mongodb` тем же
C-кодом, что и нативный драйвер. Транскодирования нет ни на одной стороне —
поэтому прежняя попытка заменить это своим рекурсивным DTO проиграла: она
добавляла второй проход по всей структуре в PHP-userland.

Зависимость узкая: в `src/` от `ext-mongodb` зависит один класс
`DocumentSerializer` плюс тайп-хинт `ObjectId` в четырёх Result-DTO. Библиотека
`mongodb/mongodb` в `src/` не используется вообще — она нужна только тестам и
бенчмаркам как нативный эталон.

## 2. Замеры, на которых стоит решение

Микробенч на реалистичном документе (10 полей, вложенность, список), 20 000
итераций:

| Операция | BSON (`ext-mongodb`) | msgpack (`ext-msgpack`) |
| --- | ---: | ---: |
| декод | 1.69 мкс | 0.87 мкс |
| энкод | 1.55 мкс | 0.51 мкс |
| размер | 441 Б | 337 Б |

Три подхода к спецтипам на одном документе (3 спецзначения среди ~15 узлов):

| Подход | Стоимость |
| --- | ---: |
| помеченные ключи + оживление обходом в PHP | 2.26 мкс |
| BSON через `ext-mongodb` (текущий) | 1.69 мкс |
| объектный формат msgpack (предлагаемый) | 1.43 мкс |

Разбивка: распаковка тех же данных без объектов — 1.01 мкс, с объектами — 1.43.
Создание трёх PHP-объектов внутри C-парсера стоит 0.42 мкс, тех же трёх обходом
в PHP — 1.26 мкс.

## 3. Механизм

`ext-msgpack` кодирует PHP-объект как map, **первый ключ которого `nil`
(`0xc0`), а значение — имя класса**; остальные пары — свойство → значение.
C-распаковщик конструирует объект прямо в точке разбора, второго прохода нет.

```
82                                    fixmap(2) — объект
  c0                                    ключ nil — маркер
  d9 26 'SConcur\...\Bson\ObjectId'     имя класса
  a3 'oid'                              свойство
  b8 '65f1c2a3b4d5e6f708192a3b'         значение
```

Проверено: байты можно собрать вручную (значит Go их эмитит), работает на любой
вложенности, `readonly` и promoted-свойства проходят, конструктор не
вызывается, неизвестный класс даёт `__PHP_Incomplete_Class`. Ключ `nil`
однозначен: PHP-массив не может иметь ключ `null` (он приводится к `''`), а
ключи BSON-документа всегда строки.

Обратное направление симметрично: `msgpack_pack` сериализует объекты нативно в
C, Go читает `nil`-ключ и мапит имя класса в тип BSON.

### Ограничения механизма

- Формат зависит от ini `msgpack.php_only`. Дефолт `1`, уровень `PHP_INI_ALL`.
  При `0` распаковка ломается (`illegal key type`, вместо объекта массив), а
  упаковка теряет класс. Нужен явный `ini_set` при инициализации плюс тест.
- Имя класса пишется целиком на каждое значение. На типичном документе это
  тонет в общей экономии (360 Б против 441 Б у BSON), но документ из одних
  идентификаторов раздувается: 100 `ObjectId` дают ~7100 Б против ~1700 Б у
  BSON. Отсюда требование к неймингу — короткий FQCN.
- Конструктор не вызывается, значит валидации в value-объектах не будет.

## 4. Решения

- **Неймспейс короткий:** `SConcur\Bson\`, а не
  `SConcur\Features\Mongodb\Bson\` — имя класса едет на проводе с каждым
  значением.
- **`ObjectId` хранит 24-символьный hex.** Сырые 12 байт вдвое компактнее, но
  hex — то, что пользователь видит и сравнивает; экономия тонет на фоне имени
  класса.
- **Классы повторяют `MongoDB\BSON\*` один в один** — те же конструкторы,
  геттеры, строковая и JSON-формы. Переход приложения на SConcur должен сводиться
  к правке `use`-строк и ничему больше. Отсюда и `Int64`: BSON int64
  декодируется в объект, ровно как это делает драйвер, иначе тип не пережил бы
  чтение с последующей записью.
- **`MinKey`/`MaxKey` — классы без свойств** (`fixmap(1)`, только `nil`-ключ).
- **Свойства `public readonly`, не `protected`.** MessagePack манглит имя
  protected-свойства так же, как `serialize()` (`\0*\0oid`), а Go пишет обычные
  имена. Публичность здесь — требование формата, не стиля; `readonly` оставляет
  объект неизменяемым.
- Валидация в конструкторах прикрывает пользовательский код; на пути распаковки
  конструктор не вызывается, поэтому входящее с провода валидирует Go.

## 5. Поддерживаемые типы

| BSON | Класс / тип PHP |
| --- | --- |
| double, string, bool, null, int32 | нативные скаляры |
| int64 | `SConcur\Bson\Int64` |
| document, array | `array` |
| objectId | `SConcur\Bson\ObjectId` |
| date | `SConcur\Bson\UTCDateTime` |
| binary | `SConcur\Bson\Binary` |
| regex | `SConcur\Bson\Regex` |
| timestamp | `SConcur\Bson\Timestamp` |
| decimal128 | `SConcur\Bson\Decimal128` |
| javascript | `SConcur\Bson\Javascript` |
| minKey / maxKey | `SConcur\Bson\MinKey` / `MaxKey` |

Плюс `stdClass`: собственного типа BSON у него нет, но объект-документ приходит в
пользовательском коде постоянно (`json_decode` без `associative`), и `ext-mongodb`
его принимал — поэтому Go разворачивает его в поддокумент. Любой другой класс —
ошибка.

## 6. Этапы

1. Инструмент замера: `tests/benchmarks/mongodb-serializer.php` — прямой
   микробенч `DocumentSerializer`, API которого не меняется, поэтому один и тот
   же скрипт даёт сравнимые «до» и «после».
2. PHP: классы `SConcur\Bson\*`.
3. Go: `bson.Raw` → msgpack одним проходом по элементам, без промежуточной
   `map[string]interface{}` (иначе весь выигрыш съедается).
4. Go: msgpack → BSON через `bsoncore`, тоже без промежуточного представления.
5. PHP: `DocumentSerializer` на `msgpack_pack`/`msgpack_unpack`, guard на
   `msgpack.php_only`, Result-DTO на новые типы.
6. `composer.json`: `ext-mongodb` из `require` убрать, `mongodb/mongodb`
   перевести в `require-dev`.
7. Тесты: round-trip всех типов (есть в
   `MongodbDocumentSerializerTest`, переписать на новые классы), плюс
   юнит-тесты кодека с обеих сторон и тест на байтовую раскладку конверта.
8. Замеры «после» тем же инструментом и теми же `bench-mongodb-*`.

## 7. Критерии приёмки

- `make check` зелёный; round-trip всех типов из раздела 5 проходит.
- Микробенч сериализатора не хуже текущего; ожидание — примерно −40% на декоде
  и −60% на энкоде.
- `bench-mongodb-{findOne,insertOne,payloadRead,payloadWrite}` не хуже базы из
  раздела 8.
- Go-сторона: замерить транскодирование отдельно (`make ext-test` +
  бенчмарк Go), поскольку сейчас там ноль работы, а станет не ноль.
- `ext-mongodb` не требуется для работы `src/` (проверяется тем, что он остаётся
  только в `require-dev`).

## 9. Результаты (2026-08-15)

### 9.1. PHP-сторона — то, ради чего всё делалось

`tests/benchmarks/mongodb-serializer.php`, 20 000 итераций, медиана трёх
прогонов. Один и тот же скрипт до и после, API `DocumentSerializer` не менялся.

| Документ | Операция | До (BSON) | После (msgpack) | Дельта |
| --- | --- | ---: | ---: | ---: |
| простой | serialize | 1.45 мкс | 0.83 мкс | −43% |
| простой | unserialize | 1.69 мкс | 0.99 мкс | −41% |
| простой | round trip | 3.14 мкс | 1.60 мкс | −49% |
| простой | размер | 458 Б | 337 Б | −26% |
| со спецтипами | serialize | 1.62 мкс | 0.71 мкс | −56% |
| со спецтипами | unserialize | 1.69 мкс | 1.39 мкс | −18% |
| со спецтипами | round trip | 3.31 мкс | 2.10 мкс | −37% |
| со спецтипами | размер | 441 Б | 400 Б | −9% |

Ожидание раздела 7 (−40% на декоде, −60% на энкоде) подтвердилось.

Обе колонки сняты одним и тем же скриптом с одной и той же фикстурой, поэтому
сравнимы между собой. Позже текст фикстуры был переведён на английский (правило
языка), из-за чего документ стал короче и текущий прогон даёт другие абсолютные
числа — на соотношение это не влияет, но воспроизвести именно эти байты нынешним
скриптом уже нельзя.

### 9.2. Go-сторона — цена, которой раньше не было

`BenchmarkConversion` в `msgpack_bench_test.go`. На сыром BSON эта работа стоила
ноль: байты драйвера уходили в PHP как есть.

| Документ | BSON → msgpack | msgpack → BSON |
| --- | ---: | ---: |
| 270 Б (типичный) | 3.53 мкс / 31 alloc | 3.68 мкс / 32 alloc |
| 1.3 КиБ | 4.07 мкс / 33 alloc | 4.80 мкс / 34 alloc |
| 16.7 КиБ | 15.9 мкс / 33 alloc | 13.7 мкс / 34 alloc |

Первый вариант был на четверть дороже; пул кодеков и предразмер буферов по длине
входа убрали лишние аллокации и до 46% времени на крупных документах.

Размен принят сознательно: работа переезжает с единственного PHP-треда в
горутину, где параллелизм есть.

### 9.3. Сквозные бенчмарки монги оказались непригодны

`bench-mongodb-*` не разрешают эффект такого размера. На одной и той же сборке
медиана пяти прогонов `findOne sync` дала 31.3 мс в одной пятёрке и 98.4 мс в
следующей — разброс втрое. Внутри одной пятёрки `payloadRead async` гулял от
8.2 до 44.4 мс.

Поэтому дельты по ним не приводятся: они измеряют состояние коллекции и
планировщик, а не кодек. Инструментами остаются 9.1 и 9.2. Если сквозная цифра
понадобится, бенчмаркам нужен отдельный ремонт — это самостоятельная работа.

Перепроверено после правок ревью (медиана пяти прогонов, мс): findOne 22.5 / 33.8
/ 46.3 → 23.6, insertOne 11.4 / 49.7 / 26.0, payloadRead 12.1 / 27.8 / 25.6,
payloadWrite 10.1 / 40.5 / 24.8 по колонкам native / sync / async. Вывод тот же, и
виден он прямо в контрольной колонке: `native` — нетронутый нативный драйвер —
разошёлся с базой раздела 8 на findOne с 14.5 до 22.5 мс, то есть шум двигает
контроль сильнее, чем изменение двигало бы измеряемое. Внутри одной пятёрки
`findOne sync` гулял от 26.0 до 164.2 мс.

### 9.4. Что вскрылось по ходу

`ext-msgpack` не повторяет объект, который уже писал: второй раз тот же
экземпляр едет ссылкой `{nil: 4, 0: <индекс>}`, где индекс — сквозной счётчик
всех записанных контейнеров (мапы, массивы, объекты и сами ссылки). Переиспользование
одной переменной `ObjectId` в документе — обычный пользовательский код, так что
декодер на Go ведёт такой же счётчик и разрешает ссылки. Закреплено тестами
`TestResolvesRepeatedObjectInstances` и `TestRejectsUnknownObjectReference` на
байтах, которые реально выдаёт PHP.

Конвертация делается ровно один раз на сообщение — в `payloads.UnmarshalParams`
либо в `serializer.Payload*` для команд, чей `dt` и есть документ. Вложенные
поля после этого уже BSON, поэтому разбор bulkWrite, опций и всё остальное
осталось нетронутым.

- Все 17 типов из раздела 5 проходят round-trip через живую MongoDB, включая

- `ext-mongodb` больше не в `require` — только в `require-dev`, где он нужен

### 9.6. Паритет с драйвером

Классы `SConcur\Bson\*` повторяют `MongoDB\BSON\*` один в один: конструкторы,
геттеры, `__toString()`, `jsonSerialize()`, `toDateTime()`/`toDateTimeImmutable()`,
константы подтипов `Binary`, сортировка флагов `Regex`, генерация `ObjectId`.
Закреплено `tests/feature/Features/Mongodb/Bson/BsonDriverParityTest.php`, который
сравнивает пары объектов бок о бок, а не с записанными литералами: проверяется
именно совпадение с драйвером, а не с однажды зафиксированным значением.

Следствие для `Collection`: счётчики результатов (`modifiedCount` и прочие)
приходят как `Int64`, как и у драйвера, поэтому читаются через `toCount()` —
`(int)` от объекта молча дал бы `1`.

### 9.7. Что нашло ревью перед релизом

Два дефекта портили данные молча, оба — на входящем пути в Go:

- **Счётчик ссылок не считал контейнеры внутри свойства объекта.** Свойство
  читалось `DecodeInterfaceLoose` целиком, а PHP нумерует каждый вложенный
  контейнер, поэтому после `Javascript` со scope повторный экземпляр `ObjectId`
  разрешался в соседний объект — без ошибки. Свойства теперь читает `decodeValue`,
  который обходит контейнеры сам и узнаёт вложенный конверт (значит, `ObjectId`
  внутри scope больше не превращается в подкарту с пустым ключом).
- **`stdClass` валил всю операцию** (`unsupported object class`), хотя на
  `ext-mongodb` объект-документ работал.

Заодно, тем же проходом: свойства читаются хелперами `property*`, которые падают
на отсутствующем свойстве и на значении не того типа или не влезающем в поле BSON
(раньше подставлялся ноль); `Timestamp`, `Int64`, `Binary` валидируют вход как
драйвер; пять случайных байт `ObjectId` берутся раз на процесс, а не на каждый id,
иначе счётчик не задаёт порядок внутри секунды.

Закреплено: `TestResolvesReferencesAfterAContainerInsideAProperty`,
`TestKeepsValueObjectsInsideAJavascriptScope`, `TestConvertsStdClassToADocument`,
`TestRejectsMalformedObjects` на Go; `testRoundTripsAScopeAndAReusedInstance`,
`testStoresAPlainObjectAsADocument` через живую монгу; проверки валидации и
процессного значения `ObjectId` — в `BsonDriverParityTest`.
