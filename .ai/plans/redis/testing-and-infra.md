# Тесты, бенчмарки, инфраструктура

## Бэкенд в docker

`docker-compose.yml` — сервис по образцу остальных бэкендов:

```yaml
  redis:
    container_name: sc-redis
    image: redis:8.2-alpine
    restart: unless-stopped
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}", "--appendonly", "no", "--save", ""]
    ports:
      - ${REDIS_DOCKER_PORT}:6379
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 3s
      timeout: 5s
      retries: 20
      start_period: 5s
    tmpfs:
      - /data:rw,noexec,nosuid,size=512m
    # volumes:
    #   - redis-data:/data
```

Пароль включён намеренно: иначе путь аутентификации не проверяется ни одним
тестом, а именно он ломается первым в чужой инфраструктуре. Закомментированный
том — та же схема, что у остальных сервисов, для длинных бенчмарк-сессий на
диске.

`.env.example` (и `.env`): `REDIS_HOST=sc-redis`, `REDIS_PORT=6379`,
`REDIS_PASSWORD=_sc_password_567`, `REDIS_DB=0`, `REDIS_DOCKER_PORT=26379`.

## Нативный драйвер

Базовая линия `native` в методологии [docs/benchmarks.md](../../../docs/benchmarks.md)
— это настоящий драйвер без SConcur (`PDO`, `mongodb/mongodb`, сырые сокеты).
Для Redis такой драйвер один: `phpredis`, C-расширение. Он же эталон в тестах на
соответствие, как `ext-amqp` и `ext-mongodb` в своих фичах.

Ставится в трёх местах, все три обязательны:

- `docker/php/Dockerfile` и `docker/release/Dockerfile` —
  `pie install phpredis/phpredis:<точная версия>` рядом с `mongodb` и `amqp`, с
  тем же комментарием о том, зачем он в образе. В оба, потому что всё, что
  нужно проверке, обязано быть в обоих образах, иначе релизная сборка ломается
  там, где локальная работает (`.ai/README.md`, «The core»);
- `composer.json`, `require-dev` — `"ext-redis": "<та же версия>"`, ровно как
  пины `ext-amqp` и `ext-mongodb`. Пин и `pie install` держатся в одной версии.

`predis` — не расширение, а библиотека на чистом PHP, и в роли `native` она не
годится: она проиграет по построению, а не по устройству, и строка таблицы с ней
измеряла бы разницу между PHP и C, а не то, что делает фича. Прецедент в проекте
уже есть — `php-amqplib` в `docs/benchmarks.md` назван в прозе как ограничение
(потребление держит PHP-поток), но не измеряется. Если строка «а что у тех, кто
живёт на чистом PHP» всё-таки понадобится, она добавляется отдельно и с явной
пометкой, что сравнивается с реализацией на PHP, а не с нативным драйвером.

## Хелпер тестов

`tests/impl/TestRedisResolver.php` по образцу `TestMysqlResolver`:

- `getConnection(?int $timeoutMs = null, ?int $poolSize = null): Connection`
- `getDsn(): string` — собирается из `$_ENV`
- `getNativeRedis(): Redis` — phpredis, база сравнения бенчмарков и тестов
  соответствия
- `flush(): void` — очистка базы между тестами; тесты работают в отдельной базе
  (`REDIS_DB`), чтобы очистка ничего чужого не задела
- `countServerConnections(): int` — число клиентских соединений по `CLIENT LIST`,
  для тестов на утечки

## Feature-тесты

`tests/feature/Features/Redis/`. Все наследуют `BaseTestCase` (напрямую или
через `BaseAsyncTestCase`) — его `tearDown` ловит зависшие задачи.

| Тест | Что проверяет |
| --- | --- |
| `RedisTest` | обязательный тест от `BaseAsyncTestCase`: две команды в `WaitGroup`, порядок событий, конкурентность (общее время ≈ самой долгой, а не сумме), путь исключения |
| `RedisCommandTest` | сырой `command()`, синхронный путь вне корутины |
| `RedisTypesTest` | отображение RESP → PHP: `null`, целые, бинарно-небезопасные значения, вложенные массивы; отказ на аргументе `bool`/`null` |
| `RedisPipelineTest` | порядок ответов, ошибка одной команды не рушит пачку, один round trip |
| `RedisTransactionTest` | `MULTI`/`EXEC`, атомарность на конкурентной записи |
| `RedisScanTest` | обход батчами, `MATCH`/`COUNT`, брошенный итератор не оставляет state (по образцу `MongodbAbandonedCursorTest`) |
| `RedisSubscribeTest` | доставка, несколько каналов и шаблонов, `add`/`remove`, `close`, брошенная подписка закрывается остановкой флоу |
| `RedisBlockingTest` | ключевой для дизайна: `BLPOP` на пять секунд не задерживает соседнюю `GET`; отказ, если дедлайн меньше блокирующего аргумента |
| `RedisErrorTest` | `WRONGTYPE` и код в исключении, отклонённые команды с текстом замены, битый DSN, неверный пароль |
| `RedisCancellationTest` | `WaitGroup::stop()` во время блокирующей команды, курсора и подписки; после остановки соединения возвращены |
| `RedisParityTest` | ответы совпадают с phpredis на матрице команд каждой группы фасада |

## Тесты ядра

`make ext-test` — юнит-тесты рядом с кодом, список в
[rust-core.md](rust-core.md#юнит-тесты-ядра). Гонки, которые PHP-набор ловит
статистически (закрытие подписки одновременно с приходом сообщения, отмена
посреди батча), проверяются именно там.

## Утечки

`tests/mem-leak/` — сценарий redis: цикл из подписок, курсоров и блокирующих
команд, каждый раунд с проверкой двух вещей — плоский RSS процесса и постоянное
число клиентских соединений по `CLIENT LIST`. Второе не менее важно первого:
воркер с ровной памятью может оставлять сокеты на стороне сервера, ровно как в
AMQP-соаке.

## Бенчмарки

`tests/benchmarks/redis/`, отдельная make-цель на операцию (правило структуры
бенчмарков):

| Цель | Что меряет |
| --- | --- |
| `bench-redis-get` | `GET` — sync, async-фан-аут, phpredis |
| `bench-redis-set` | `SET` в тех же трёх режимах |
| `bench-redis-pipeline` | пачка из N команд против N одиночных |
| `bench-redis-fan-out` | N корутин по одной команде: мультиплексирование против последовательного phpredis |
| `bench-redis-value-size` | размер значения 100 Б / 10 КБ / 1 МБ — где граница съедает выигрыш |
| `bench-redis-pool-size` | `poolSize` 1/2/4/8 — им определяется значение по умолчанию |

Ожидаемые вердикты, которые надо подтвердить, а не предположить: синхронный путь
проигрывает phpredis (цена границы, как у всех фич); async-фан-аут выигрывает
тем сильнее, чем больше одновременных команд; на мегабайтных значениях выигрыш
съедается копированием.

Строки в `docs/benchmarks.md` (обе языковые версии) добавляются по методологии
файла: каждая ячейка вердикта самодостаточна и называет, что с чем сравнивалось.

## Демо-нагрузка

Маршрут в демо-сервере (`tests/servers/http`), делающий несколько команд Redis
на запрос, — чтобы фича попадала и в нагрузочные прогоны, а не только в
микробенчмарки. Ставится последним, вместе с бенчмарками, и только если он не
меняет цифры существующих маршрутов.
