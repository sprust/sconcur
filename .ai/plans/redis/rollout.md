# Этапы, версия, доки

## Этапы

Каждый заканчивается зелёным `make check` (cs-fixer, PHPStan, `ext-build`,
`ext-check`, тесты) — правило проекта, а не пожелание.

1. Инфраструктура. Сервис `redis` в `docker-compose.yml`, переменные в
   `.env.example`, `phpredis` в обоих образах и пин `ext-redis` в `require-dev`
   `composer.json`, `TestRedisResolver`. Ничего функционального; проверка —
   контейнеры поднимаются, `composer install` проходит, phpredis видит сервер.
2. Каркас фичи. `MethodEnum::Redis`, `Method::Redis`, пустой модуль
   `ext/src/features/redis/` с диспетчером, регистрация в `features/mod.rs` и
   `shutdown()`, реестр на `Core`, разбор DSN, бамп версии расширения (один раз
   на ветку, все четыре источника). Проверка — `PING` через `command()`.
3. Обычные команды. Пул мультиплексированных соединений, сборка `Cmd`, списки
   отклоняемых команд, кодирование значений, исключения. Тесты:
   `RedisCommandTest`, `RedisTypesTest`, `RedisErrorTest`, обязательный
   `RedisTest` от `BaseAsyncTestCase`.
4. Пайплайн и транзакция. `Pipeline`, `Dto\ErrorReply`, `transaction()`.
5. Блокирующие команды. Выделенные соединения, согласование дедлайна с
   блокирующим аргументом, `RedisBlockingTest` — тест, ради которого этот
   механизм и существует.
6. Курсоры. `scan_state`, `ScanResult`, тест брошенного итератора.
7. Pub/Sub. Реестр подписок, поток сообщений, `add`/`remove`/`close`, тесты
   доставки и отмены.
8. Типизированный фасад. Трейты по группам команд, `RedisParityTest` против
   phpredis.
9. Бенчмарки и гейт. Цели `bench-redis-*`, значение `poolSize` по умолчанию из
   цифр, строки в `docs/benchmarks.md` (обе версии).

   Что померилось (localhost, 2000 вызовов, медиана 5 прогонов): `get` — native
   30.1 мс против async 52.1; `set` — 26.0 против 52.6; пайплайн из 20 команд —
   7.2 против 7.9. phpredis выигрывает во всех формах, и это ожидаемо: `GET` к
   локальному Redis отвечает за ~11 мкс, а это дешевле одного пересечения
   границы. Батч закрывает разрыв почти полностью. `poolSize`: 1 → 51.3 мс,
   2 → 45.6, 4 → 45.1, 8 → 44.9 — по умолчанию 4.

   Вырезать по гейту нечего: фича целится в незаблокированный воркер и в Redis
   по сети, чего бенчмарк на localhost показать не может. Это сказано в доке
   прямо, по образцу раздела AMQP.
10. Доки и завершение. `docs/redis.md` + `docs/redis.ru.md`, README (обе
    версии), `.ai/README.md`, mem-leak-сценарий, финальный `make check`.

Что всплыло по ходу и стоит помнить: redis-rs по умолчанию ставит покомандный
таймаут 500 мс (`DEFAULT_RESPONSE_TIMEOUT`) и на мультиплексированное соединение,
и на `ConnectionManager`. Он выключен — дедлайн здесь один, из payload; иначе
любая блокирующая команда обрывалась бы через полсекунды.

Этапы 4–8 независимы между собой и опираются только на 1–3.

## Версия расширения

Новый метод и новые payload — изменение протокола PHP↔расширение, значит
минорный бамп: `0.12.2` → `0.13.0`, один раз на ветке, все четыре источника в
одном коммите (`ext/src/lib.rs`, `ext/Cargo.toml`,
`src/Connection/Extension.php`, `composer.json`). Мажорный не трогаем.
`VersionConsistencyTest` проверяет равенство против загруженного ядра.

## Доки

- `docs/redis.md` и `docs/redis.ru.md`: быстрый старт, DSN и его параметры,
  сырой путь против типизированного фасада, пайплайн и транзакция, блокирующие
  команды, курсоры, подписки, типы и их отображение, отклонённые команды и чем
  их заменить, ограничения (нет кластера, нет `WATCH`, подписка занимает
  соединение, `SCAN` не даёт снимка), внутренности (мультиплексирование,
  выделенные соединения, подметание пула).
- README и `README.ru.md`: строка в «What it replaces» (phpredis/predis), ссылка
  в списке фич, строка roadmap — снимается, когда фича поставлена.
- `.ai/README.md`: фича в списках PHP-слоя и модулей ядра, `Redis`/`rds` и
  `RedisCommandEnum` в разделе перечислений, ссылка на доку, запись о
  mem-leak-сценарии.
- Ссылок на этот план нигде за пределами `.ai/` быть не должно — ни в коде, ни в
  `docs/`, ни в makefile.

Доки пишутся по правилам раздела «Documentation style»: каждое техническое
утверждение сверено с кодом, минимум жирного, никакого нерасшифрованного
жаргона, обе языковые версии в одном коммите.
