# Протокол PHP↔расширение

Обязательные требования [docs/adding-a-feature.md](../../../docs/adding-a-feature.md)
соблюдаются в каждом обработчике: отмена через `task.context()` и дедлайн из
payload, ограничивающий операцию.

## Метод

Новый метод верхнего уровня, значение свободно среди существующих:

- PHP: `SConcur\Features\MethodEnum` → `case Redis = 'rds';`
- Rust: `ext/src/types/method.rs` → `Method::Redis`, `b"rds"` в `from_wire` и
  `"rds"` в `as_wire`
- регистрация: `ext/src/features/mod.rs` → `Method::Redis => Ok(redis::get())`,
  и `redis::close_all()` в `shutdown()`

## Конверт

Форма как у `Sql` (`BaseSqlPayload`): суб-операция, настройки соединения, тело
команды. Один PHP-класс `Payloads\RedisPayload` на все команды — по образцу
`Amqp\Payloads\AmqpPayload`: у команд Redis нет параметров с логикой, они
плоские, и два десятка почти одинаковых классов ничего не дают сверх именованного
аргумента на месте вызова.

| Ключ | Тип | Значение |
| --- | --- | --- |
| `cm` | string | суб-операция, `RedisCommandEnum` |
| `dsn` | string | адрес и параметры соединения |
| `to` | int | дедлайн выполнения, мс (обязателен) |
| `ps` | int | размер пула мультиплексированных соединений, `0` — по умолчанию |
| `cl` | int | максимальное время жизни соединения, мс, `0` — без ограничения |
| `dt` | map | тело команды |

Rust: `payloads::Envelope` в `ext/src/features/redis/payloads.rs`, поля с
`serde(rename)` ровно по этим ключам, перекрёстная ссылка на PHP-класс в
докблоке — в обе стороны, как требует гайд.

### DSN в каждом сообщении

`Sql` шлёт DSN с каждой командой, `Amqp` — хендл, полученный при `connect()`.
Здесь взят вариант `Sql`: соединения пулятся по DSN, PHP-объект `Connection` не
владеет сокетом и не нуждается в жизненном цикле.

Цена честная: строка DSN (порядка 30–50 байт) едет через границу на каждой
команде, а команды Redis — самые маленькие payload в проекте. Если бенчмарк
покажет, что это заметная доля стоимости `GET` (ориентир — больше 3% времени
одной операции на синхронном пути), включаем оптимизацию: расширение отвечает на
первую команду коротким хендлом `cid`, PHP-объект его кеширует и дальше шлёт
вместо DSN, а неизвестный хендл (после `fork`, после `destroy`) откатывает
вызывающего на DSN. Это довесок к конверту, а не другая его форма, поэтому
решение можно принимать по цифрам после v1.

## Суб-операции

`SConcur\Features\Redis\RedisCommandEnum`, значение в `cm`. Каждый case называет
Rust-структуру, в которую декодируется его `dt` (правило `AmqpCommandEnum`).

| Case | `cm` | Назначение |
| --- | --- | --- |
| `Command` | `cmd` | одна команда |
| `Pipeline` | `pip` | пачка команд одним round trip, опционально в `MULTI`/`EXEC` |
| `Scan` | `scn` | курсорная команда семейства `SCAN`, стриминг батчами |
| `Subscribe` | `sub` | подписка, стриминг сообщений |
| `SubscriptionUpdate` | `sup` | добавить/убрать каналы у живой подписки |
| `SubscriptionClose` | `suc` | закрыть подписку |

### `cmd` — одна команда

| Ключ | Тип | Значение |
| --- | --- | --- |
| `n` | string | имя команды в верхнем регистре (`GET`, `HSET`) |
| `a` | list | аргументы, каждый — строка байт |
| `bl` | int | `0` — решает расширение по имени, `1` — блокирующая, `2` — точно не блокирующая |

`bl` трёхзначный, потому что по имени видно не всё: `BLPOP` блокирующая всегда,
`XREAD` — только с `BLOCK`, и знает об этом тот, кто собрал аргументы. Список
безусловно блокирующих команд лежит в расширении, `bl=1` его дополняет, `bl=2`
перекрывает.

Ответ — значение RESP, упакованное в MessagePack (см. «Типы»).

### `pip` — пайплайн

| Ключ | Тип | Значение |
| --- | --- | --- |
| `c` | list | команды, каждая — `{n, a}` |
| `at` | bool | обернуть в `MULTI`/`EXEC` |

Ответ — карта `{r: [ответы], e: {индекс: {c: код, m: текст}}}`. При `at=true`
`r` — это содержимое ответа `EXEC`, либо `null`, если транзакцию отменил `WATCH`
(в v1 `WATCH` недоступен, форма сохраняется на будущее).

Ошибка одной команды не рушит весь ответ: сервер выполнил остальные, и PHP
подставляет объект-ошибку на её место по индексу. Отказы едут рядом с ответами, а
не на месте ответа: помеченную карту внутри значения подделывает любой хеш с
таким полем.

`EXEC`, отклонённый на этапе постановки в очередь (`EXECABORT`), — это отказ
всей задачи, а не элемент списка: сервер не выполнил ничего.

### `scn` — курсорная команда

| Ключ | Тип | Значение |
| --- | --- | --- |
| `n` | string | `SCAN`, `HSCAN`, `SSCAN`, `ZSCAN` |
| `a` | list | аргументы без курсора (`MATCH …`, `COUNT …`, ключ для H/S/Z) |
| `bs` | int | сколько элементов отдавать в одном батче PHP |

Курсор живёт в расширении, PHP тянет батчи через `next()` — та же машинерия, что
у `RowsResult`. `COUNT` управляет round trip'ами к серверу, `bs` — пересечениями
границы; это разные числа, и путать их в доке нельзя.

### `sub` / `sup` / `suc` — подписка

`sub`:

| Ключ | Тип | Значение |
| --- | --- | --- |
| `ch` | list | каналы (`SUBSCRIBE`) |
| `pt` | list | шаблоны (`PSUBSCRIBE`) |
| `bs` | int | максимум сообщений в одном батче |

Первый результат несёт `sid` — идентификатор подписки (это `task_key` state'а) и
подтверждение подписки; дальше каждый `next()` отдаёт батч уже пришедших
сообщений. Батч — не задержка: state отдаёт то, что готово, и ждёт только когда
не готово ничего. Одно сообщение — `{k, c, p, d}`: вид (`msg` или `pmsg`),
канал, шаблон (для `pmsg`), тело.

`sup` (`{sid, op, ch, pt}`, где `op` — `add`/`rem`) и `suc` (`{sid}`) идут
отдельными задачами и маршрутизируются к соединению подписки по `sid`.

Шардированных каналов (`SSUBSCRIBE`) в v1 нет: `redis::Msg` не отличает
`smessage` от `message`, а отличать их пришлось бы, чтобы честно сказать в
`k`. Смысл они имеют только в кластере, который тоже v2, — так что вырезано
целиком, а не наполовину.

## Типы

RESP → MessagePack → PHP. Расширение не интерпретирует ответы по именам команд:
что сервер прислал, то и едет.

| RESP | PHP |
| --- | --- |
| Null | `null` |
| Integer | `int` |
| Simple string, Bulk string | `string`, бинарно-безопасно (msgpack `bin`) |
| Array | `list<mixed>` |
| Error | ошибка задачи → исключение |

RESP3 в v1 отклонён на уровне DSN. Кодировщик его варианты понимает (они
достижимы и без него), но обещать, что типизированные методы прочитают обе формы,
оказалось нельзя: угадывать форму по декодированному PHP-массиву неверно в обе
стороны — хеш с полями `0` и `1` выглядит как плоский список.

Обратно, PHP → RESP: `string` как есть, `int` и `float` — их десятичная запись.
`bool`, `null`, массив и объект отклоняются исключением на стороне PHP, до
пересечения границы.

## Ошибки

Ошибка задачи несёт вид отказа, который написало ядро: `redis[<kind>]: <текст>`,
где kind — один из `cmd`, `conn`, `timeout`, `refused`, `arg`, `dsn`, `stopped`,
`state` (`ext/src/features/redis/errors.rs`). PHP читает тег и поднимает
соответствующее исключение; всё после тега для него непрозрачно. Вид пишут все
пути, включая стриминговые состояния: курсор, у которого вышел дедлайн, обязан
приехать `RedisTimeoutException`, а не `RedisCommandException` без кода.

Классифицировать по тексту нельзя, и это не теоретическая осторожность:
половину текста пишет сервер, а `redis.error_reply('connect: ...')` в
Lua-скрипте выбирал бы, какое исключение поймает приложение — включая два,
которые `LogicException` и потому проходят мимо `catch (RedisException)`.

Для `cmd` текст начинается с кода Redis (`WRONGTYPE`, `NOSCRIPT`, `MOVED`,
`LOADING`), и PHP отделяет его в поле `errorCode` — одно разделение по первому
пробелу, код только если слово из заглавных латинских букв.
