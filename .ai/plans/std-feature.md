# Фича Std: стандартные функции PHP с выполнением в расширении

`Std::*` реализует SConcur-эквиваленты стандартных функций PHP, чьи нативные вызовы
блокируют PHP-поток целиком: `password_hash()` считает десятки миллисекунд, и этого не
прерывает даже автоматическая преемпция (см.
[docs/coroutine-switching.ru.md](../../docs/coroutine-switching.ru.md), «О чём стоит
помнить»). Вызов уезжает в задачу рантайма: PHP-поток свободен, соседние корутины
продолжают работать.

Файловые операции из этого плана вынесены в [files-feature.md](files-feature.md):
домен на два десятка команд со стримингом придавил бы здесь sleep и пароли.

## Состав v1

Решения владельца (зафиксированы):

- v1 — две группы команд: `sleep`/`usleep` (поглощают `Sleeper`) и
  `password_hash`/`password_verify`. Больше ничего. Файлы — своя фича,
  [files-feature.md](files-feature.md).
- json, hash и gzip в v1 не входят. Они остаются кандидатами, и войдут только если
  бенчмарк покажет выигрыш — см. «За бенчмарк-гейтом».
- `Sleeper` удаляется жёстко, без deprecated-фасада.
- Фича делается на своей ветке со своим минорным бампом версии.

Список урезан потому, что оставшиеся группы — те, где выигрыш не зависит от результата
замера: они либо ждут (sleep), либо считают достаточно долго, чтобы цена границы не
имела значения (`password_*`).

## Цель и не-цели

- Цель: ни один вызов стандартной функции не замораживает воркер. Блокирующий вызов
  подвешивает только свою корутину. Единый API для sync и async, как у каждой фичи.
- Цель: настоящий параллелизм для `password_*` — N хешей занимают N задач рантайма
  на разных ядрах, пока PHP-поток обслуживает другие запросы.
- Не-цель: замена быстрых функций. `base64_*`, `str_*` и им подобные дешевле
  границы; они остаются нативными.
- Не-цель: байт-идентичный вывод там, где замешано PHP-специфичное форматирование.

## Целесообразность

### Цена границы PHP↔расширение

Каждый вызов — msgpack-конверт, переход через границу и минимум две копии памяти в
каждую сторону. Синхронный путь всегда медленнее нативного вызова: граница
прибавляется к той же работе. Позиционирование фичи — код в корутинах и серверных
обработчиках; вне корутин нативные функции остаются правильным выбором (кроме sleep,
где семантика та же).

### password_*: самый однозначный кандидат

`password_hash` намеренно медленный (bcrypt cost 10 — ~50–100 мс, argon2id —
настраиваемо больше), полностью CPU-bound, строки крошечные — граница бесплатна. Один
логин-запрос сегодня замораживает весь воркер на это время; со `Std` — только свою
корутину. Это флагманский кейс фичи.

Оговорка совместимости: форматы (`$2y$`, `$argon2id$...`) обязаны быть взаимно
проверяемыми с нативными `password_verify`/`password_hash` — иначе миграция на фичу и
обратно ломает существующие базы хешей. Тесты interop в обе стороны обязательны;
дефолтные параметры повторяют PHP (bcrypt cost 10; argon2 — memory/time/threads как в
`PHP_PASSWORD_ARGON2_*`).

### Файловые операции

Вынесены в [files-feature.md](files-feature.md) — там же разбор, где выигрыш реален, а
где граница только мешает.

### Память и рантайм расширения

- Фан-аут CPU-команд грузит те же ядра, на которых крутятся SO_REUSEPORT-соседи по
  per-core пулу: выигрыш одного воркера может стать деградацией пула под полной
  нагрузкой. В доку — оговорка: Std решает латентность и хвосты, throughput CPU-bound
  по-прежнему масштабируется процессным пулом.

## За бенчмарк-гейтом (не v1)

Ни одна из этих команд не входит в поставку, пока замер не покажет выигрыш на
асинхронном пути. Причины сомнений известны заранее и записаны здесь, чтобы гейт не
переоткрывали каждый раз с нуля.

- **json.** Для `jsonEncode` PHP-значение сначала пакуется в MessagePack на
  PHP-потоке — это сам по себе монолитный вызов; для `jsonDecode` результат
  распаковывается из msgpack там же. Со структуры снимается только генерация и
  парсинг текста, сериализация остаётся на PHP. Выигрыш в разы, не на порядки.
- **hash.** `hash()` в PHP — C-реализация со скоростью порядка ГБ/с; sha256 на 100 КБ
  считается доли миллисекунды. Расширение не быстрее; единственный выигрыш —
  освобождение PHP-потока на больших payload. Отдельно стоит `hashFile`: он не двигает
  байты через границу вообще, и потому живёт в [files-feature.md](files-feature.md), а
  не здесь.
- **gzip.** `flate2` надо сравнить с C-шным zlib до того, как это станет API. Выход не
  байт-в-байт с `gzencode` (метаданные заголовка, разбиение на блоки при том же
  уровне), так что корректность проверяется только раундтрипом через `gzdecode`.

Общее для всех трёх: на payload меньше десятков КБ граница дороже самой работы, и
выигрыша нет даже в async.

## API

Статический фасад (как старый `Sleeper`), `src/Features/Std/Std.php`:

```php
use SConcur\Features\Std\Std;

Std::sleep(seconds: 1);                                  // поглощает Sleeper::sleep
Std::usleep(microseconds: 100);                          // поглощает Sleeper::usleep

$hash  = Std::passwordHash($password);                   // bcrypt/argon2id
$valid = Std::passwordVerify($password, $hash);
```

Внутри корутины вызов подвешивает файбер и выполняется конкурентно; снаружи это
обычный блокирующий вызов (синхронный путь `FeatureExecutor`).

## Протокол и механика

- Один новый метод `MethodEnum::Std` (`std`) с командным конвертом (`StdCommandEnum`,
  паттерн HttpClient/Sql — поле `cm` выбирает суб-операцию): Sleep `slp`,
  PasswordHash `pwh`, PasswordVerify `pwv`. C-ABI не тронут — фича это данные.
- PHP: `src/Features/Std/` — `Std.php`, `StdCommandEnum`, `Payloads/*` (каждый несёт
  обязательный дедлайн `timeoutMs`), исключения в `SConcur\Exceptions\Std\*`,
  именованные по случаю. `src/Features/Sleeper/` удаляется.
- Rust: `ext/src/features/std/` — `mod.rs` (диспатч по команде), `payloads.rs`,
  `sleep.rs`, `password.rs`. `ext/src/features/sleeper/` удаляется;
  `MethodEnum::Sleep` (`sl`) убирается из PHP и из ядра.
- Оба обязательных требования
  [docs/adding-a-feature.md](../../docs/adding-a-feature.md) соблюдаются: каждый
  обработчик уважает отмену через `task.context()`, а дедлайн из payload ограничивает
  операцию.

## Бенчмарк-гейт

Каждая команда до релиза проходит гейт: native vs sync vs async (`tests/benchmarks/`,
методология
[docs/benchmarks.md](../../docs/benchmarks.md)). Команда, чей async не даёт реального
выигрыша, в поставку не идёт. Ожидаемые вердикты: sync-путь всегда проигрывает
нативному (цена границы, как у остальных фич); выигрыши — одновременное выполнение и
«PHP-поток остаётся свободен».

## Сознательно исключено

- `preg_*` — RE2 ≠ PCRE не «тонкое расхождение», а другая семантика (нет backtracking,
  lookbehind, рекурсии). Молчаливая подмена движка — прямой путь к неотлаживаемым
  багам у пользователей.
- `serialize`/`unserialize` — PHP-специфичный формат.
- `base64_*` и прочие дешёвые преобразования — быстрее границы.
- `openssl_*` шифрование — возможно позже, не v1.

## Семантические допуски (фиксируются в docs/std.md)

- `passwordHash`/`passwordVerify`: кодированные форматы (`$2y$`, `$argon2id$...`)
  взаимно проверяемы с нативными `password_verify`/`password_hash` — interop-тесты
  закрепляют это в обе стороны.
- Отмена: sleep отменяется немедленно; `password_*` проверяет контекст перед стартом и
  не прерывается посреди операции.

## Миграция Sleeper (жёсткое удаление)

- `Sleeper::sleep/usleep` → `Std::sleep/usleep` везде: feature-тесты, бенчмарки,
  stress- и mem-leak-тесты, демо-серверы (`tests/servers/http|ws`), пример quick-start
  в README (оба языка), доки.
- `src/Features/Sleeper/`, `ext/src/features/sleeper/` и `MethodEnum::Sleep`
  удаляются. Без BC-фасада — проект pre-1.0 и экспериментальный.

## Версионирование

Новый метод + payloads + удалённый метод = изменение протокола PHP↔расширение →
минорный бамп версии расширения, один раз на ветке фичи, все источники вместе — их
список в `.ai/README.md`, раздел «Extension versioning».

## Тесты

- На команду: корректность против нативной функции, синхронный путь, пути ошибок
  (неизвестный алгоритм → исключение, именованное по случаю, с цепочкой `previous`).
- Interop: `Std::passwordHash` проверяется нативным `password_verify` и наоборот.
- Конкурентность: N тяжёлых `passwordHash` одновременно завершаются за ~max, а не
  ~sum, плюс проверка уровня сервера, что один такой вызов в обработчике не задерживает
  лёгкий запрос (E2E-паттерн coroutine-switching).
- Отмена: `WaitGroup::stop()` и shutdown во время sleep.
