# Объекты через MessagePack

PHP и расширение обмениваются каждым payload и каждым результатом в формате
MessagePack. У скаляров, массивов и карт есть собственный тип MessagePack — они
пересекают границу как есть. Значение, у которого такого типа нет — идентификатор,
дата, decimal, — пересекает её как PHP-объект, в той же кодировке, которой
`ext-msgpack` уже пользуется для объектов.

Этот документ — справочник по механизму: формат, ограничения, которые он
накладывает на обе стороны, как добавить тип и как его тестировать.

Единственная фича, использующая механизм сегодня, — MongoDB: её классы
`SConcur\Bson\*` и есть те объекты-значения, которые она отдаёт приложению (см.
[mongodb](mongodb.ru.md)). Поэтому все примеры ниже — из этого набора. Сам механизм
от фичи не зависит.

## Где происходит конвертация

На стороне PHP:

| Направление | Точка входа |
|---|---|
| PHP → расширение, payload | `Transport\MessagePackTransport::pack` — пакует `PayloadInterface::getData()` |
| расширение → PHP, результат задачи | `Transport\MessagePackTransport::unpack` |
| PHP → расширение, документ MongoDB | `Features\Mongodb\Serialization\DocumentSerializer::serialize` |
| расширение → PHP, документ или пачка курсора | `DocumentSerializer::unserialize` / `::unserializeBatch` |

Каждая точка — один вызов `msgpack_pack()` или `msgpack_unpack()`. PHP никогда не
обходит раскодированную структуру: `ext-msgpack` собирает объекты на C прямо в
разборе, а второй проход по каждому документу в userland стоил бы дороже самого
декодирования.

На стороне расширения (на примере MongoDB):

| Направление | Точка входа |
|---|---|
| PHP → расширение, `dt` — структура параметров | `payloads::decode_params` |
| PHP → расширение, `dt` — сам документ | `serializer::document_from_msgpack` / `documents_from_msgpack` |
| расширение → PHP, один документ | `serializer::document_to_msgpack` |
| расширение → PHP, пачка курсора | `serializer::documents_to_msgpack` |

Каждая конвертирует ровно один раз, на внешней кромке сообщения. Всё, что внутри,
дальше уже BSON — обход bulkWrite, разбор опций и код каждой команды читают его
напрямую.

## Конверт

Объект — обычная карта MessagePack, первый ключ которой `nil`, а значение при нём —
имя класса; дальше идут пары «свойство/значение». Упакуйте объект и посмотрите на
байты:

```shell
docker compose exec php php -d extension=./ext/build/sconcur.so \
  -r 'require "vendor/autoload.php";
      echo bin2hex(msgpack_pack(["id" => new SConcur\Bson\ObjectId("6919e3d1a3673d3f4d9137a3")])), PHP_EOL;'
```

```
81                                    fixmap(1) — документ
  a2 'id'                             имя поля
  82                                    fixmap(2) — здесь начинается объект
    c0                                    ключ nil — маркер
    b5 'SConcur\Bson\ObjectId'            имя класса
    a3 'oid'                              имя свойства
    b8 '6919e3d1a3673d3f4d9137a3'         значение свойства
```

Ключ `nil` однозначен: PHP-массив не может держать ключ `null` — он приводится к
`''`, — поэтому обычная карта не может начинаться с такого ключа. Распаковщик на C
узнаёт эту форму прямо в разборе и создаёт объект в этой точке.

Расширение пишет ту же форму через `write_object_header`
(`serializer/to_msgpack.rs`), поэтому значение, пришедшее из драйвера,
оказывается в PHP объектом без единого действия со стороны
PHP.

## Флаг расширения

Кодировка существует только при включённом `msgpack.php_only`. С выключенным оба
направления деградируют тихо — ничего не падает:

- упаковка объекта теряет класс и имена свойств, остаётся список значений: массив
  `["id" => new ObjectId("6919…")]` пакуется как `81 a2 6964 91 b8 …` и читается
  обратно как `['id' => ['6919…']]`;
- распаковка байтов, которые написало расширение, выдаёт
  `Warning: [msgpack] (msgpack_unserialize_map_item) illegal key type` и отдаёт
  обычный массив, в котором ключ `nil` привёлся к `''`.

Настройка объявлена как `PHP_INI_ALL`, поэтому SConcur не просто требует её, а
включает принудительно при инициализации расширения — в `Extension::checkExtension()`,
которая выполняется один раз при построении синглтона. Сборка, отказавшаяся принять
изменение, падает там с `MsgpackObjectSupportDisabledException`, а не портит
документы позже. Эта же проверка убеждается, что `ext-msgpack` вообще загружен.

Включение происходит один раз при инициализации, так что код, меняющий настройку
после этого, действует на свой страх и риск: никто не переустанавливает её на каждой
операции.

Настройка действует на весь процесс, то есть и на ваши собственные вызовы
`msgpack_pack()`. Если приложение пакует MessagePack для потребителя на другом языке,
пакуйте массивы, а не объекты: при включённом флаге объект уедет в PHP-конверте,
который читает обратно только PHP.

## Версия расширения

Конверт — деталь реализации `ext-msgpack`, а не документированный формат обмена.
Ничто не обязывает расширение сохранять его между релизами, и изменение не заявит о
себе: документы продолжат ходить, просто обычными массивами без своих типов.

Поэтому `composer.json` фиксирует точную версию, на которой проект протестирован, —
`"ext-msgpack": "3.0.1"`, а не диапазон. Относитесь к этому пину как к части
механизма, а не как к общей осторожности с зависимостями: поднять его — значит
перепрогнать тесты, которые держат формат, прежде всего `TestObjectEnvelopeLayout` и
`TestResolvesRepeatedObjectInstances` в the serializer's unit tests: они проверяют раскладку
байтов и нумерацию ссылок против того, что PHP действительно выдаёт. Прошли на новой
версии — пин можно двигать; упали — сначала правится кодировщик и декодировщик.

## Повторные экземпляры

`ext-msgpack` не пишет один и тот же объект дважды. Второе появление того же
экземпляра становится ссылкой — `{nil: 4, 0: <индекс>}`, — где индекс считает все
контейнеры, записанные к этому моменту: карты, массивы, объекты и сами ссылки,
нумерация с 1. Переиспользовать один объект-значение внутри документа — обычный код,
поэтому декодировщик расширения ведёт такой же счётчик и разрешает ссылки по нему
(`converter` в `ext/src/features/mongodb/serializer/`).

```shell
docker compose exec php php -d extension=./ext/build/sconcur.so \
  -r 'require "vendor/autoload.php";
      $objectId = new SConcur\Bson\ObjectId("6919e3d1a3673d3f4d9137a3");
      echo bin2hex(msgpack_pack(["x" => $objectId, "y" => $objectId])), PHP_EOL;'
```

```
82                                    fixmap(2) — документ, контейнер 1
  a1 'x'
  82 c0 b5 'SConcur\Bson\ObjectId' …    объект, контейнер 2
  a1 'y'
  82                                    fixmap(2) — ссылка, контейнер 3
    c0 04                                 ключ nil, маркер 4
    00 02                                 ключ 0 — указывает на контейнер 2
```

Считается каждый контейнер, в том числе тот, что лежит внутри свойства самого
объекта, — например, scope у `Javascript`. Пропустить такой контейнер не значит
упасть: ссылка попадёт в соседний объект, и документ молча унесёт неверное значение.
Именно поэтому свойство читает `decodeValue`, который сам обходит контейнеры, а не
отдаёт их декодировщику целиком; `TestResolvesReferencesAfterAContainerInsideAProperty`
держит это на байтах, которые PHP выдаёт по-настоящему.

## Каким должен быть PHP-класс

Два ограничения идут от формата обмена, а не от вкуса:

- свойства должны быть `public` — MessagePack искажает имя `protected`-свойства так
  же, как `serialize()` (`"\0*\0oid"`), а расширение пишет обычные имена. Объявите
  класс `readonly`, чтобы объект всё равно остался неизменяемым. Это единственное
  место, где не действует правило проекта «свойства — `protected`», и классы в
  `src/Bson/` несут комментарий об этом.
- конструктор не вызывается, когда расширение создаёт объект при декодировании,
  поэтому валидация в нём защищает только пользовательский код. То, что пришло с
  провода, валидируется на стороне расширения — хелперами `property*`, описанными ниже.

Кроме того: дайте классу интерфейс-маркер (`SConcur\Bson\Type` для набора BSON), чтобы
обход документа мог его опознать, и держите имя класса коротким — оно едет по проводу
с каждым значением.

## Кодировщик

`write_value` в `serializer/to_msgpack.rs` имеет ветку на исходный тип:
`write_object_header(buffer, class, properties)`, а следом пары «имя
свойства/значение» в том порядке, в котором их объявляет PHP-класс.

`write_object_header` пишет карту из `properties + 1` пар, первая из которых — `nil`
→ имя класса. Число свойств, не совпадающее с реально записанными парами, ломает
поток: декодировщик по обе стороны прочитает следующее значение как ключ.

## Декодировщик

`serializer/from_msgpack.rs` раскодирует payload в дерево значений и обходит его,
превращая карты в BSON:

- `document_from_walked` читает карту и спрашивает, не `nil` ли её первый ключ —
  признак конверта, — и передаёт конверт в `read_envelope`;
- `read_envelope` читает имя класса и свойства и записывает экземпляр под его
  индексом контейнера, а повтор разрешает по этому индексу;
- `bson_from_envelope` превращает раскодированный объект в элемент BSON — по ветке
  на имя класса; неизвестный класс это ошибка;
- хелперы `property_*` (`property_string`, `property_bytes`, `property_int`,
  `property_range`) читают по одному свойству. Они падают на свойстве, которого
  нет, у которого не тот тип или которое не влезает в целевое поле, — вместо того
  чтобы подставить ноль, который уехал бы в базу настоящей датой или настоящим
  подтипом.

Счётчик контейнеров — причина, по которой здесь обход дерева, а не потока: каждую
карту и каждый массив нужно пронумеровать в том же порядке, в каком их нумерует
`ext-msgpack`, и на обходе дерева это верно тривиально.

## Как добавить тип

Четыре места, в таком порядке:

1. PHP-класс — в `src/Bson/` для значения BSON или в пространстве имён своей фичи в
   остальных случаях. Публичные свойства, `readonly`-класс, интерфейс-маркер: см.
   [Каким должен быть PHP-класс](#каким-должен-быть-php-класс). Если класс повторяет
   класс из другой библиотеки, повторяйте его точно: тот же конструктор, те же
   геттеры, тот же `__toString()` и `jsonSerialize()`.
2. Кодировщик, `write_value` в `serializer/to_msgpack.rs`: ветка для исходного типа,
   который пишет `encodeObjectHeader(encoder, class, propertyCount)` и пары свойств.
   Константу с именем класса добавьте к остальным в начало файла.
3. Декодировщик, `bson_from_envelope` в `serializer/from_msgpack.rs`: ветка для имени класса,
   который читает свойства хелперами `property*` и дописывает значение.
4. Тесты — следующий раздел.

Затем пересоберите расширение и прогоните проверки:

```shell
make ext-build
make check
```

## Как это тестировать

Тип, который не переживает круговой рейс, отлавливается сразу. Остальная часть набора
нужна для случаев, которые сами по себе не падают: переставленный конверт,
неправильно посчитанная ссылка, класс, разошедшийся с библиотекой, которую он
повторяет.

### Круговой рейс, в расширении

`TestRoundTripsEveryBSONType` в the serializer's unit tests — первое место для нового типа: он
строит документ со значением каждого типа, прогоняет его через
`BSONToMsgpack` → `MsgpackToBSON` и сравнивает результат побайтово, так что
расхождение в любую сторону падает там. `TestRoundTripsNestedSpecialValues` делает то
же для значения внутри вложенного документа и внутри массива.

Хелперы в этом файле — `roundTrip` (закодировать, раскодировать, упасть на ошибке) и
`buildDocument` (упаковать `bson.D`).

### Фиксация раскладки на байтах, которые PHP выдаёт по-настоящему

Круговой рейс доказывает только то, что расширение согласно само с собой. То, что пишет PHP,
фиксируется отдельно, и фикстуры берутся из PHP, а не пишутся руками:

```shell
docker compose exec php php -d extension=./ext/build/sconcur.so \
  -r 'require "vendor/autoload.php";
      echo bin2hex(msgpack_pack([<проверяемое значение>])), PHP_EOL;'
```

Вставьте шестнадцатеричную строку в тест и раскодируйте её через `MsgpackToBSON`.
Существующие тесты, с которых стоит списывать:

| Тест | Что держит |
|---|---|
| `TestObjectEnvelopeLayout` | форму конверта: две пары, первым `nil`, затем класс — перестановка деградировала бы в обычный массив на стороне PHP, а не упала |
| `TestResolvesRepeatedObjectInstances` | форму ссылки и нумерацию контейнеров |
| `TestResolvesReferencesAfterAContainerInsideAProperty` | нумерацию, когда контейнер лежит внутри свойства |
| `TestKeepsValueObjectsInsideAJavascriptScope` | что объект-значение внутри свойства остаётся объектом |
| `TestConvertsStdClassToADocument`, `TestConvertsAnEmptyStdClass` | что обычный PHP-объект становится вложенным документом |
| `TestRejectsUnknownObjectClass`, `TestRejectsUnknownObjectReference` | что неизвестный класс или висячая ссылка — ошибка, а не молчаливый пропуск |

Ради читаемости эти тесты собирают payload из кусков хелперами `fixedString` и
`objectIdEnvelope`, а не одной длинной шестнадцатеричной строкой.

### Сторона PHP

| Тест | Что держит |
|---|---|
| `tests/feature/Features/Mongodb/Bson/BsonDriverParityTest.php` | каждый объект-значение против его двойника `MongoDB\BSON\*` — строковую форму, JSON-форму, весь набор геттеров; сравнение идёт бок о бок, а не с литералом, потому что обещание тут — соответствие библиотеке, а не значению, записанному однажды |
| `tests/feature/Features/Mongodb/Serialization/MongodbDocumentSerializerTest.php` | полный круговой рейс через живую MongoDB: записать значения, прочитать обратно, проверить типы |
| `tests/feature/Connection/MsgpackObjectSupportTest.php` | что инициализация принудительно включает `msgpack.php_only`, — проверяется в дочернем процессе, запущенном с выключенной настройкой |

Новый тип получает строку в провайдере теста соответствия и значение в тесте
сериализатора.

### Цена

`make bench-mongodb-serializer`
измеряет только упаковку/распаковку в PHP, без базы и без расширения. Стоит смотреть,
когда тип добавляется в документ, который и так большой: имя класса едет с каждым
значением.

### Команды

```shell
make ext-build                                    # сначала пересобрать ext/build/sconcur.so
make ext-test                                     # собственные тесты ядра
make test c="--filter=BsonDriverParityTest"       # один PHP-тест
make check                                        # cs-fixer, phpstan, тесты PHP, тесты ядра
```

## Подводные камни

| Случай | Поведение |
|---|---|
| Пустой документ | уезжает пустым массивом MessagePack, а не пустой картой: пустую карту `ext-msgpack` раскодирует в `stdClass`, тогда как все прочие документы раскодируются в массив. PHP всё равно имеет один тип и для `{}`, и для `[]` |
| Обычный PHP-объект (`(object) [...]`, `json_decode()` без `associative: true`) | пакуется конвертом `stdClass` и превращается во вложенный документ; читается обратно массивом |
| Любой другой объект, для которого нет `case` в `appendObject` | это ошибка — значению нечем стать на целевой стороне |
| Целое число | сужается до int32, если влезает, — поэтому у MongoDB `int64` нуждается в классе-обёртке, чтобы пережить чтение с последующей записью |
| Бинарная строка | `bin` и `str` в MessagePack — разные коды; декодировщик принимает оба для строкового свойства, а значение `bin` без конверта становится обычным бинарным полем |
| Числовой ключ карты | PHP пишет его целым числом; декодировщик отдаёт его десятичной строкой |
