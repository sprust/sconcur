# Files

Асинхронные файловые операции. Вся операция — открытие, позиционирование,
чтение, запись, ожидание диска — происходит внутри расширения, поэтому
PHP-поток свободен, пока она идёт. Внутри `WaitGroup` много операций выполняются
одновременно; вне её тот же API работает синхронно.

Ради этого фича и существует. Один маленький файл с горячим page cache быстрее
прочитать нативно — к той же работе добавляется пересечение границы, — и
[бенчмарки](benchmarks.ru.md) говорят это прямо. Выигрыш в другом: поток не
занят, пока медленный диск отвечает, и есть операции, чьи байты вообще не
пересекают границу.

## Быстрый старт

```php
use SConcur\Features\Files\Files;
use SConcur\Features\Files\FileWriteMode;

$contents = Files::read(path: '/var/app/storage/report.csv');

Files::write(
    path: '/var/log/app/audit.log',
    contents: $line,
    mode: FileWriteMode::Append,
);

// байты не попадают в PHP
Files::copy(source: '/tmp/upload', destination: '/var/app/storage/file.bin');

// один переход границы вместо file_exists + is_file + filesize + filemtime
$stat = Files::stat(path: '/var/app/storage/file.bin');
```

Внутри `WaitGroup::add(...)` те же вызовы выполняются одновременно.

## Где выигрыш есть, а где нет

| Операция | Против чего | Вердикт |
| --- | --- | --- |
| `copy` 64 МиБ | `copy()` в PHP | в 2 раза быстрее синхронно, в 9 — одновременно: байты остаются внутри расширения |
| `list` 10 000 записей с метаданными | `scandir()` + `filesize()` + `filemtime()` на запись | в 1,8 раза быстрее одновременно; посзаписные syscall'ы до PHP не доходят |
| `hashFile` 64 МиБ | `hash_file()` | в 1,3 раза быстрее одновременно; цикл чтения не держит PHP-поток |
| `readChunks` 64 МиБ | `Files::read()` того же файла | те же байты при пике 4 МБ вместо 132 МБ |
| `read`/`write` 64 МиБ | `file_get_contents()` / `file_put_contents()` | медленнее: содержимое пересекает границу; покупается свободный поток, а не пропускная способность |
| что угодно на файле 1 КиБ с горячим кэшем | нативная функция | медленнее, и повода брать фичу здесь нет |

Цифры — в [бенчмарках](benchmarks.ru.md). Две вещи они не измеряют, и обе — суть
фичи: корутина, ждущая диск, не держит воркер, и запрос, читающий большой файл,
больше не задерживает все остальные запросы процесса.

## Дедлайны и отмена

Каждый вызов принимает `timeoutMs`, по умолчанию `Files::DEFAULT_TIMEOUT_MS`
(30 000). `0` — без дедлайна.

Дедлайн здесь значит, что вызывающий перестаёт ждать, — а не что syscall
прерван. Файловая работа идёт в blocking-пуле рантайма, и поток, уже вошедший в
`read(2)`, останется там, пока ядро не вернёт управление. Для операции, идущей
кусками — стриминговое чтение, копирование, обход дерева, чанки писателя, —
отмена настоящая: она проверяется между кусками, и недописанный файл удаляется.

Размер этого пула и ограничивает, сколько файловых операций процесс выполняет
одновременно: 64 по умолчанию, задаётся через `SCONCUR_BLOCKING_THREADS`.

## Чтение и запись

```php
Files::read(
    path: '/var/app/storage/report.csv',
    offsetBytes: 0,
    lengthBytes: 0,
    maxReadBytes: Files::DEFAULT_MAX_READ_BYTES,
);
```

| Параметр | Что значит |
| --- | --- |
| `offsetBytes` | с какого места читать; вместе с `lengthBytes` заменяет `fopen` + `fseek` + `fread` |
| `lengthBytes` | сколько читать; `0` — до конца файла |
| `maxReadBytes` | отказывает на файле больше лимита с `FileTooLargeException`; по умолчанию 64 МиБ, `0` снимает лимит |

Лимит нужен потому, что разовое чтение держит файл дважды — в расширении и в
PHP. У `readChunks()` такого пика нет, и такого лимита тоже.

```php
Files::write(
    path: '/var/log/app/audit.log',
    contents: $line,
    mode: FileWriteMode::Append,
    permissions: 0644,
);
```

`FileWriteMode` — это `Replace` (создать или обрезать, как `w`), `Create`
(создать, отказав, если путь занят, как `x`) и `Append` (создать или дописать,
как `a`). `permissions` применяются только при создании файла, как у `open(2)`.

Неудачная запись убирает то, что создала сама, и не трогает остальное: `Create`,
отказавший из-за занятого пути, не удаляет файл, ставший причиной отказа, а
дозапись не удаляет никогда.

### Атомарная запись

```php
Files::writeAtomic(path: '/var/app/cache/routes.php', contents: $compiled);
```

Пишет временный файл рядом с целевым, сбрасывает его на диск и переименовывает
поверх. Одновременный читатель видит либо старое содержимое, либо новое, никогда
полузаписанное. Временный файл — сосед, потому что переименование атомарно
только внутри одной файловой системы.

## Копирование, перемещение, удаление

```php
$copiedBytes = Files::copy(source: $source, destination: $destination);

Files::move(source: '/tmp/upload-9f2c', destination: '/var/app/storage/42.jpg');

Files::delete(path: $path, missingOk: true);
Files::truncate(path: $path, sizeBytes: 0);
```

`copy` стримит файл внутри расширения; границу пересекают только путь и число.
Принимает те же `mode` и `permissions` плюс `bufferSizeBytes`, задающий
гранулярность копирования.

`move` переименовывает внутри одной файловой системы и копирует с удалением
между двумя — ровно то, что делает `rename()` в PHP.

`delete` с `missingOk` считает отсутствующий путь успехом и отвечает, было ли
что-то действительно удалено: гонка «проверить и удалить», написанная один раз
здесь, а не на каждом месте вызова.

## Контрольные суммы

```php
use SConcur\Features\Files\FileHashAlgorithm;

$digest = Files::hashFile(path: $path, algorithm: FileHashAlgorithm::Sha256);
```

Hex в нижнем регистре, под теми же именами, что знает `hash_file()`, так что
сумма, записанная одной стороной, проверяется другой. Алгоритмы: `Sha256` (по
умолчанию), `Sha512`, `Sha1` и `Md5`; последние два — ради ETag'ов и
существующих манифестов, а не как выбор в пользу безопасности.

Как и `hash_file()`, ничего не держит целиком. В отличие от него, цикл чтения и
все ожидания диска в нём идут на рантайме.

## Метаданные

```php
$stat = Files::stat(path: $path, followSymlinks: true);
```

Отвечает объектом `Dto\FileStat`: `exists`, `isFile`, `isDirectory`,
`isSymlink`, `sizeBytes`, `modifiedAtMs`, `accessedAtMs`, `createdAtMs`,
`permissions`, `userId`, `groupId`.

Отсутствующий путь — не ошибка: `exists` равно false, остальные поля держат
нулевые значения. Именно это позволяет `Files::exists()` быть чтением того же
результата, а не отдельной командой.

`permissions` несёт только биты прав, без битов типа над ними, поэтому
сравнивается с `0644` без масок. Времена — миллисекунды от эпохи,
отрицательные для отметки до неё и `0` там, где файловая система времени не
хранит.

```php
Files::exists(path: $path);
Files::chmod(path: $path, permissions: 0600);
Files::touch(path: $path, modifiedAtMs: 0);      // 0 — сейчас
Files::realPath(path: $path);
Files::temporaryFile(directory: '/var/app/tmp', prefix: 'upload-', suffix: '.bin');
```

`touch` создаёт файл, если его нет, и никогда не меняет содержимое. `realPath`
отказывает на отсутствующем пути с `FileNotFoundException`, а не отвечает тем
`false`, который так легко забыть проверить.

`temporaryFile` выбирает имя и создаёт файл одним шагом, поэтому нет окна, в
которое имя уведёт другой процесс, — а у `tempnam()` с последующим `fopen()` оно
есть. Пустой `directory` означает системный временный каталог.

## Каталоги

```php
Files::makeDirectory(path: '/var/app/storage/exports/2026-09', permissions: 0755, recursive: true);
Files::removeDirectory(path: '/var/app/storage/tmp', recursive: true);

$entries = Files::list(path: $directory, pattern: '*.csv', withMetadata: true);
```

`makeDirectory` с `recursive` создаёт родителей и считает существующий каталог
успехом — поведение `mkdir -p`. Без него существующий каталог даёт
`FileAlreadyExistsException`. `permissions` подчиняются umask процесса, как у
`mkdir(2)`.

`removeDirectory` требует `recursive` для каталога, в котором ещё есть записи.

`list` отвечает списком `Dto\DirectoryEntry` (`name`, `path`, `isDirectory`,
`isSymlink`, `sizeBytes`, `modifiedAtMs`), отсортированным по имени. Без
`withMetadata` запись не стоит ни одного stat, а её `sizeBytes` и
`modifiedAtMs` равны `null` — «не спрашивали», а не «пусто».

`pattern` фильтрует внутри расширения, поэтому каталог на сто тысяч файлов не
едет через границу ради фильтрации в PHP. Он понимает `*`, `?` и `[...]` против
имени записи; это не `glob(3)` — нет `**`, нет раскрытия фигурных скобок и нет
экранирования, а шаблон никогда не переходит через разделитель каталогов.

`list` читает один каталог. Дерево — это `walk()`.

## Стримы

### Чтение батчами

```php
foreach (Files::readChunks(path: $path, bufferSizeBytes: 65536) as $chunk) {
    $digest->update($chunk);
}

foreach (Files::readLines(path: '/var/log/app/access.log') as $line) {
    // ...
}
```

`readChunks` держит один буфер при любом размере файла, тогда как `read()`
держит файл дважды. `readLines` режет строки в расширении — именно поэтому батч
строк стоит одного перехода границы там, где `fgets()` в цикле стоит по одному
на строку; разделители убираются, `\r\n` в том числе, а последняя строка без
терминатора остаётся строкой.

`readLines` принимает `batchSize` (строк за переход), `bufferSizeBytes` и
`maxLineBytes` — последний ограничивает одну строку, чтобы файл без переводов
строки нельзя было забуферизовать целиком во имя стриминга.

### Обход дерева

```php
foreach (Files::walk(path: $directory, pattern: '*.tmp') as $entry) {
    Files::delete(path: $entry->path);
}
```

Фронтир живёт в расширении, поэтому выход после первого совпадения стоит первого
каталога и не более того. Шаблон выбирает, что попадает в ответ, а не куда идёт
обход.

Символьные ссылки на каталоги перечисляются, но внутрь них обход не заходит. Это
сделано намеренно: у дерева со ссылкой на собственного предка нет конца.

### Запись чанками

```php
$writer = Files::openWriter(path: '/var/app/storage/export.csv');

foreach ($rows as $row) {
    $writer->write(chunk: implode(',', $row) . "\n");
}

$writtenBytes = $writer->close();
```

`write()` не отвечает, пока расширение не записало чанк, поэтому корутина,
производящая быстрее, чем принимает диск, ждёт на своём же следующем вызове, а
не копит мегабайты в памяти.

Не закрыть — безопасно, но с потерей: когда корутина заканчивается, вместе с ней
заканчивается флоу, и расширение закрывает файл, удаляя его, если запись не была
завершена, — кроме режима дозаписи. `close()` — это то, что превращает байты в
законченный файл и отвечает общим числом.

### Брошенный стрим

Выйти досрочно из любого из них безопасно. Флоу заканчивается, и расширение
освобождает то, что стрим держал. Прогон на сто тысяч циклов брошенных
читателей, обходов и писателей держится ровно.

## Ошибки

Каждая ошибка названа по своему случаю. Вид ошибки решается в расширении и
читается из сообщения, а не вылавливается из него: файл с именем «permission
denied» не должен выбирать, какое исключение поймает приложение.

| Исключение | Случай |
| --- | --- |
| `FileNotFoundException` | пути нет |
| `FilePermissionException` | процессу нельзя делать с ним это |
| `FileAlreadyExistsException` | путь назначения занят, а режим запрещает замену |
| `UnexpectedFileTypeException` | каталог там, где нужен файл, или наоборот, или каталог, в котором ещё есть записи |
| `FileTooLargeException` | файл больше лимита чтения, который нёс вызов |
| `FileTimeoutException` | дедлайн истёк |
| `FileWriterClosedException` | писателя или стрима, названного этой ручкой, больше нет |
| `FileOperationException` | любая другая ошибка ввода-вывода |
| `InvalidFileArgumentException` | неверен сам вызов |

Все, кроме последнего, наследуются от `FilesException`, а тот — от
`RuntimeException`: отсутствующий файл и полный диск остаются условиями
исполнения, что бы вызывающий ни делал. `InvalidFileArgumentException` — это
`LogicException`, намеренно вне этого дерева: отрицательная длина или
неизвестный алгоритм — ошибка в коде, и обработчик, написанный под сбои файловой
системы, не должен её проглатывать.

## Чего фича не делает

- **Нет дескриптора в духе `fopen`** с `seek`, `tell`, `read` и `write`. Каждый
  такой вызов был бы переходом границы ради самой дешёвой вещи, какая есть.
  Произвольный доступ — это `read(offsetBytes, lengthBytes)`, последовательный —
  стримы.
- **Нет блокировок.** `flock`, переживающий подвешивание, требует дескриптора,
  живущего в расширении, и модели владения им. `writeAtomic()` закрывает то,
  ради чего блокировку обычно и берут.
- **Нет слежения за файловой системой**, нет `symlink`/`readlink`, нет
  `glob(3)`, нет `fgetcsv` — разбор остаётся в PHP поверх `readLines()`.
