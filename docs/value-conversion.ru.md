# Значения через границу

Как PHP-значение попадает в ядро на Rust и как значение из ядра попадает в PHP. Ни в
одну сторону ничего не сериализуется: ядро читает PHP-массив, с которым вызвана
задача, и само строит PHP-значения результата, и то и другое на PHP-потоке. Этот
документ — справочник по механизму: дерево значений, соответствие каждого типа PHP,
объекты, как фича (модуль расширения со своим PHP API) этим пользуется и как добавить
класс-значение. Где именно переход сидит в жизненном цикле задачи — в
[архитектуре](architecture.ru.md).

## Два направления

C-обвязка — это `ext/sconcur.c`: слой на C, который вызывает PHP и который сам
вызывает ядро на Rust.

| Направление | Где | Что происходит |
|---|---|---|
| PHP → ядро, параметры задачи | `SConcur\Extension\push()`, `ext/sconcur.c`, `read_value` в `ext/src/lib.rs` | C-обвязка отвечает, что собой представляет каждый zval; ядро читает массив в дерево `dto::Value` до возврата из вызова |
| ядро → PHP, результат задачи | экспорты `wait*`, `write_value` в `ext/src/lib.rs`, строитель значений в `ext/sconcur.c` | ядро обходит дерево `Value`, которое построила фича, а C-обвязка пишет zval на место |

Оба работают внутри вызова, который сделал PHP, на PHP-потоке: значение Zend можно
трогать только там. Задача фичи работает на потоках рантайма и zval не видит
никогда, она видит дерево.

## Дерево значений

В `ext/src/dto/value.rs` один тип на оба направления:

| Вариант | Значение PHP |
|---|---|
| `Value::Nil` | `null` |
| `Value::Bool` | `bool` |
| `Value::Int` | `int` (64 бита, со знаком) |
| `Value::Float` | `float` |
| `Value::Str(Vec<u8>)` | `string`, текст или байты без разницы: в PHP один тип на оба |
| `Value::List(Vec<Value>)` | массив с ключами `0..n` по порядку |
| `Value::Map(Vec<(Key, Value)>)` | любой другой массив в порядке вставки; `Key` — `Int` или `Str` |
| `Value::Object(Object)`, `Object { class, properties }` | объект любого другого класса (не `stdClass`, не `Closure` и не вариант enum): полное имя и публичные свойства |

`Map` строится через `Map::new().set("key", value)`; скаляры, строки, векторы байт,
`Vec<Value>` и `Option` превращаются в `Value` через `.into()`. `Value::uint`
отдаёт беззнаковое число как `Int`, пока оно влезает, и как `Float` за
`i64::MAX` — так же поступает сам PHP.

## PHP → ядро

Читатели значений в C-обвязке (`sconcur_zval_kind`, `sconcur_zval_long`,
`sconcur_zval_string`, `sconcur_array_iterate`, `sconcur_object_iterate`, …)
отвечают на один вопрос о zval каждый; два вызова обхода идут по контейнеру и
вызывают ядро на каждую запись. Правила чтения:

- ссылка читается насквозь; неинициализированное типизированное свойство
  пропускается;
- массив — `List`, когда PHP говорит, что его ключи `0..n`, иначе `Map`, и
  пустой массив — это пустой `List`;
- `stdClass` читается как `Map` своих свойств;
- любой другой объект — `Value::Object` с именем класса и публичными свойствами;
  protected и private свойства в значение не входят;
- `Closure`, вариант enum, ресурс: push падает с ошибкой, которая это называет;
- дерево может быть вложено на 256 уровней; глубже push падает, а не переполняет
  стек;
- если таблицу свойств строит пользовательский код (инициализатор ленивого
  объекта) и он бросает, push падает; исключение летит как из любого вызова.

Фича объявляет параметры структурой с `#[derive(Deserialize)]` и заполняет её через
`message.payload.decode::<T>()`. Serde-сторона — `ext/src/dto/value_de.rs`, и она
следует PHP, а не какому-то формату:

| Тип поля | Принимает |
|---|---|
| `String` | строку в UTF-8; байты не в UTF-8 отклоняются |
| `Vec<u8>` с `#[serde(deserialize_with = "crate::dto::value_de::bytes")]` | любую строку, одной копией; `nullable_bytes` читает `null` как отсутствие байт |
| `i64`, `u32`, … | int в диапазоне цели; float и строка отклоняются |
| `f64` | float или int |
| `bool` | bool |
| `Option<T>` | `null` или `T` |
| `Vec<T>` | список; строка никогда не сходит за список |
| `HashMap<String, T>`, структура | карту, пустой массив или публичные свойства объекта; целочисленный ключ читается как его десятичный текст |
| `Value` | поддерево как есть, включая класс объекта |
| `Borrowed<'a>` с `#[serde(borrow)]` | ссылку внутрь сообщения вместо копии — для нетипизированного тела команды, которое подоперация декодирует позже |

Отсутствующее поле берёт свой `#[serde(default)]`; неизвестное поле игнорируется.
Читатели `Value` (`get`, `as_str`, `as_list`, `as_map`, `entries`,
`Object::property`) — для фичи, которая обходит значение вручную, как конвертер
MongoDB обходит документ.

## Ядро → PHP

Фича кладёт `Value` в `Result::success(message, value, execution_ms)`. Когда вызов
ожидания со стороны PHP забирает результат, `write_value` обходит дерево, а
строитель значений в C-обвязке (`sconcur_value_*`, `sconcur_array_*`, `sconcur_object_*`
в `ext/sconcur.c`) пишет каждый узел:

- `List` и `Map` оба становятся PHP-массивом (`array_init_size`, затем по слоту на
  запись); строковый ключ `Map`, равный десятичной записи целого, становится этим
  целым ключом, как в литерале массива;
- `Object` становится экземпляром названного класса, созданным без конструктора;
  каждое названное свойство пишется в свой объявленный слот. Класс ищется через
  автозагрузчик один раз на запрос и кэшируется; незагружаемый класс или свойство,
  которого класс не объявляет, роняют ожидание с `Error`, который это называет;
- `Str` — одна `zend_string`, какие бы байты она ни несла.

Слоты контейнера выдаются по одному: дочерний элемент записывается до того, как
запрошен слот следующего, потому что добавление в PHP-массив может сдвинуть его
содержимое.

Сам результат — экземпляр `SConcur\Dto\TaskResultDto`, который так же строит
строитель результатов: имена свойств, объявленных в `src/Dto/TaskResultDto.php`, —
то, что ищет строитель, поэтому переименование или добавление свойства — правка
`ext/sconcur.c` в том же коммите.

## Классы-значения

PHP-класс, экземпляры которого пересекают границу как `Value::Object`, — это
класс-значение. Сегодня такие есть у фичи MongoDB, `SConcur\Bson\*` (см.
[mongodb](mongodb.ru.md#конвертация-объектов)); сам механизм от фичи не зависит.
Два требования идут от механизма:

- свойства, которые ядро читает и пишет, публичные и объявленные: protected
  свойство не пересечёт границу на входе, а необъявленное упадёт на выходе.
  Объявляйте класс `readonly`, чтобы объект-значение всё равно оставался
  неизменяемым;
- конструктор не вызывается, когда экземпляр создаёт ядро, так что валидация в нём
  защищает только пользовательский код. То, что приходит из PHP, проверяется на
  стороне ядра (вспомогательные функции `property_*` конвертера MongoDB падают на
  отсутствующем или не того типа свойстве вместо того, чтобы подставить ноль).

Имя класса стоит держать коротким: оно едет с каждым значением.

## Как добавить класс-значение

1. PHP-класс с публичными свойствами, `readonly`, точно повторяющий двойника, если
   он его повторяет (конструктор, геттеры, `__toString()`, `jsonSerialize()`).
2. Вход: ветка в конвертере фичи, сопоставляющая `object.class` и читающая свойства
   через `Object::property(name)` — у MongoDB это `bson_from_object` в
   `ext/src/features/mongodb/serializer/from_value.rs`.
3. Выход: ветка, строящая `Value::object(class, properties)` со свойствами в порядке
   объявления (по соглашению; строитель находит слот по имени) — у MongoDB это
   `bson_value` в `serializer/to_value.rs`.
4. Тесты: юнит-тесты конвертера на обе ветки (собрать `Value`, которым читается
   PHP-экземпляр, и проверить результат; построить результат и проверить класс,
   имена и порядок свойств), плюс PHP-тест фичи, который записывает значение и
   читает обратно.

Затем пересобрать и прогнать проверки:

```shell
make ext-build
make check
```

## Цена

Каждый переход конвертирует ровно один раз, на границе: чтение внутри `push`,
сборка внутри ожидания, а между ними задача фичи работает с деревом или со своими
типами. `tests/benchmarks/runtime/boundary-profile.php` оценивает получение
результата, `push-profile.php` — отправку задачи, `request-profile.php` — что
HTTP-сервер делает с событием запроса; см.
[бенчмарки](benchmarks.ru.md#стоимость-конвертации-граница-phpрасширение).

## Подводные камни

| Случай | Поведение |
|---|---|
| Пустой PHP-массив | приходит пустым `List`; каждый читатель карты его принимает, `as_map` отвечает пустой картой |
| Строка там, где ждут список | отклоняется, а не читается как список своих байт |
| Поле `Vec<u8>` без атрибута `bytes` | компилируется, но строка для него отклоняется: аннотируйте поле |
| Целое за пределами `i64` | прийти не может: int в PHP 64-битный; на выходе `Value::uint` делает из него float |
| Две ссылки на один экземпляр в одном массиве | читаются дважды; на другой стороне ничего не разделяется |
