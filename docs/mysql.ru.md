# MySQL (универсальная SQL-фича)

Асинхронная работа с реляционной БД поверх Go `database/sql`. Каждый запрос уходит
в Go-расширение и выполняется в горутине, пока корутина приостановлена, поэтому
десятки запросов идут параллельно. Вне `WaitGroup` тот же API работает синхронно.

Фича не зависит от драйвера: ядро `SConcur\Features\Sql` ничего не знает о
конкретной БД, а `SConcur\Features\Mysql\Connection` — тонкий фасад, задающий
драйвер MySQL (`MethodEnum::Mysql`). [PostgreSQL](pgsql.ru.md) — зеркальный фасад
поверх того же ядра.

## Быстрый старт

```php
$connection = new \SConcur\Features\Mysql\Connection(
    dsn: 'user:pass@tcp(127.0.0.1:3306)/app?parseTime=true',
    timeoutMs: 5000,
);

// стриминг строк (крупные выборки не буферизуются целиком)
foreach ($connection->query('SELECT id, name FROM users WHERE age > ?', [18]) as $row) {
    echo $row['name'] . PHP_EOL;
}

// вся выборка сразу
$rows = $connection->fetchAll('SELECT * FROM users WHERE id = ?', [$id]);

// мутация: affectedRows + lastInsertId
$result = $connection->exec('INSERT INTO users (name) VALUES (?)', ['Ann']);
echo $result->lastInsertId;
```

Внутри `WaitGroup::add(...)` те же вызовы идут конкурентно.

## DSN и биндинги

- DSN — формат go-sql-driver/mysql:
  `user:pass@tcp(host:port)/dbname?param=value`. Полезные параметры:
  `parseTime=true` (даты как `time.Time`), `charset`, `loc`.
- `interpolateParams=true` фасад `Mysql\Connection` добавляет в DSN по умолчанию,
  если флага там ещё нет. Тогда запрос с биндингами идёт одним round-trip'ом
  (COM_QUERY с клиентской интерполяцией значений) вместо PREPARE + EXECUTE +
  CLOSE — быстрее на синхронном пути и совпадает с дефолтным поведением PDO;
  экранирование делает драйвер. Чтобы вернуть серверные prepared statements,
  передайте `interpolateParams=false` явно.
- Плейсхолдеры — родные для драйвера `?`. Биндинги — позиционный список; SQL не
  переписывается, значения уходят драйверу параметрами (целые нормализуются в
  int64, дробные в float64), что защищает от SQL-инъекций.

## Транзакции

Транзакция закреплена за одним соединением на всю серию команд:

```php
$transaction = $connection->begin();

try {
    $transaction->exec('UPDATE accounts SET balance = balance - ? WHERE id = ?', [100, $from]);
    $transaction->exec('UPDATE accounts SET balance = balance + ? WHERE id = ?', [100, $to]);
    $transaction->commit();
} catch (\Throwable $exception) {
    $transaction->rollback();

    throw $exception;
}
```

`begin(int $isolationLevel = 0, bool $readOnly = false)` принимает уровень
изоляции (значения `sql.IsolationLevel` из Go; `0` — дефолт драйвера) и флаг
только-чтения. У `Transaction` те же `query`/`fetchAll`/`exec`, что у соединения.

Если транзакцию бросили без `commit()`/`rollback()` (исключение, ранний выход,
остановка `WaitGroup`), Go-сторона откатывает её сама: транзакция привязана к
контексту задачи begin, а он отменяется при остановке флоу. На синхронном пути
деструктор `Transaction` дополнительно освобождает удерживаемый флоу. Внутри
одного `WaitGroup` каждая корутина держит свою транзакцию на своём соединении,
поэтому транзакции идут параллельно.

## Параметры соединения

| Параметр | Дефолт | Назначение |
|---|---|---|
| `dsn` | — | строка подключения драйвера |
| `timeoutMs` | 30000 | дедлайн одного exec; для query — на всю жизнь курсора |
| `maxOpenConns` | 0 (без лимита) | `SetMaxOpenConns` пула |
| `maxIdleConns` | = `maxOpenConns` | `SetMaxIdleConns` пула |
| `connMaxLifetimeMs` | 0 (без лимита) | `SetConnMaxLifetime` пула |

`timeoutMs` ограничивает каждый отдельный exec; для query он переносится в
стриминговый курсор и ограничивает всю его жизнь — включая каждый батч `next()` и
потребление на стороне PHP, так что медленный `foreach` по большой выборке может
упереться в него посреди итерации. На жизнь транзакции он не распространяется —
она живёт до commit/rollback или остановки флоу.

## Пул соединений и конкурентность

Каждая операция выполняется на соединении из пула `*sql.DB`, который живёт в
Go-расширении и переиспользуется между задачами и корутинами. Пул общий для всех
`Connection` с одинаковыми DSN и размерами (ключ — `драйвер+dsn+размеры`);
неиспользуемый пул, к которому не обращались дольше 5 минут, закрывается, а все
пулы закрываются при остановке расширения. Если `maxIdleConns` не задан, берётся
значение `maxOpenConns` — иначе Go держит только 2 простаивающих, пул схлопывается
после каждого веера, и следующий веер снова платит за рукопожатия.

В `WaitGroup` каждая autocommit-операция и каждая транзакция берут отдельное
соединение на время выполнения. Запустите `N` корутин с безлимитным пулом — и
откроете до `N` соединений сразу, **упершись в лимит сервера**
(`max_connections`, ошибка MySQL `1040 Too many connections`). Поэтому держите
`maxOpenConns` `<= max_connections` и в соответствии с нужной степенью
параллелизма:

```php
$connection = new \SConcur\Features\Mysql\Connection(
    dsn: 'user:pass@tcp(127.0.0.1:3306)/app',
    maxOpenConns: 50,
);
```

При насыщенном пуле autocommit-запросы `database/sql` ставит в очередь до
освобождения соединения (backpressure), а не роняет ошибкой. Транзакция держит
соединение всю свою жизнь, поэтому при `maxOpenConns` меньше числа корутин лишние
`begin()` блокируются и транзакции идут волнами — держите пул не меньше ожидаемого
числа одновременных транзакций.

## Внутреннее устройство

- Реестр пулов (`ext/internal/features/sql/pools.go`) — `*sql.DB` по ключу-структуре
  `драйвер+dsn+размеры пула`, с refcount и вытеснением простаивающих пулов (как пул
  клиентов MongoDB). Sweeper обходит реестр раз в минуту.
- Стриминг SELECT (`rows_state.go`) — `rowsState` держит `*sql.Rows` и отдаёт
  строки батчами (`batchSize` приходит со стороны PHP, там дефолт 50; `<= 0` —
  один неограниченный батч) с заглядыванием на строку вперёд, чтобы понять, есть ли
  следующий батч. Закрывается при исчерпании, раннем `break` или остановке флоу.
- Транзакции (`transactions.go`) — `begin` кладёт `transactionSession` (с
  `*sql.Tx`) в `pendingTransactions` по ключу удерживающей задачи begin и держит
  эту задачу живой (`hasNext`), чтобы соединение пережило серию команд;
  `commit`/`rollback` финализируют сессию идемпотентно (`sync.Once`).

## Ограничения

- Типы значений. Go-сторона нормализует прочитанное: `[]byte` → строка,
  `time.Time` → строка RFC3339 с наносекундами; целые, дробные, булевы и `NULL`
  проходят как есть. На MySQL это значит: целые → `int`, `FLOAT`/`DOUBLE` →
  `float`, `VARCHAR`/`TEXT`/`CHAR` и бинарные (`BLOB`/`BINARY`) → строка,
  `DECIMAL` → строка (чтобы не терять точность),
  `DATE`/`DATETIME`/`TIMESTAMP` при `parseTime=true` → строка RFC3339, `NULL` →
  `null`. Беззнаковый `BIGINT` больше `PHP_INT_MAX` выходит за диапазон знакового
  64-битного int — храните и читайте такие значения строкой.
- Курсор внутри транзакции нужно либо дочитать, либо заменить на `fetchAll` до
  следующей команды той же транзакции — иначе соединение занято открытым курсором.
- Действуют общие ограничения библиотеки — см. [README](../README.ru.md).
